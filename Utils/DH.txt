积分商城分销系统需求规格说明书
系统概述
本系统为积分商城分销系统，采用三端架构：客户端（用户端，APP+小程序）、商家端（B端，APP+小程序）、管理端（PC后台）。系统围绕"厂商→一级经销商→二级经销商→终端客户"的积分流转链路，实现积分分发、商品兑换、商品券核销等核心业务。
________________________________________
一、身份体系与积分流转
1.1 身份定义
系统共存在四类身份角色，各角色之间不存在固定的隶属绑定关系，仅通过积分流转产生业务往来：
身份角色	使用端	积分来源	积分去向
厂商/平台方	管理端	系统创建（唯一入口）	分发给一级经销商
一级经销商	客户端 + 商家端	厂商分发	赠送给任意二级经销商或终端客户
二级经销商	客户端 + 商家端	一级经销商赠送	赠送给任意终端客户
终端客户	客户端	任意经销商赠送	仅用于兑换商品，不可赠送
1.2 积分流转关系图
 
核心原则：
•	只有厂商可以创建积分（通过管理端分发给一级经销商）
•	经销商只能将自己持有的积分赠送出去，无法凭空创建
•	积分赠送不受账户创建关系限制：经销商可以给任意下游角色赠送积分，无需事先建立绑定关系
•	典型场景：二级经销商从一级经销商进货，一级经销商赠送积分给他；顾客到二级经销商店里消费，二级经销商赠送积分给顾客——该顾客无需是该经销商注册的会员
1.3 权限边界说明
一级经销商与二级经销商均具备双重身份：在客户端作为普通用户可兑换商品，在商家端作为商家可为下游用户赠送积分和核销商品券。终端客户仅能使用客户端，积分只能用于兑换商品，不可向他人赠送。

二、账户注册流程
2.1 账户创建权限
各角色账户的创建权限如下，账户创建关系仅代表"谁有权限创建该账户"，不代表业务上的绑定或隶属关系：
被创建角色	创建方	创建位置
一级经销商	厂商	管理端
二级经销商	一级经销商	商家端
终端客户	一级/二级经销商 或 客户自主注册	商家端 / 客户端
2.2 一级经销商账户创建（管理端操作）
厂商在管理端创建一级经销商账户时，需填写经销商名称、联系人姓名、手机号码。系统向该手机号发送短信验证码，厂商需在界面填入验证码完成验证后，系统自动生成初始登录密码并以短信形式发送至经销商手机。一级经销商首次登录后强制修改密码。
 
2.3 二级经销商账户创建（商家端操作）
一级经销商在商家端创建二级经销商账户，填写经销商名称、联系人姓名、手机号码。系统向该手机号发送短信验证码，一级经销商需填入验证码完成验证。验证通过后系统创建账户并将初始密码发送至二级经销商手机。二级经销商首次登录后强制修改密码。
2.4 终端客户账户创建
终端客户账户创建存在两种方式：
方式一：经销商主动创建（商家端操作）
一级或二级经销商在商家端填写客户姓名、手机号，系统发送短信验证码，经销商填入验证码后完成创建。系统将初始密码发送至客户手机，客户首次登录后强制修改密码。
方式二：客户自主注册（客户端操作）
客户在客户端APP或小程序自主注册时，需填写手机号并接收短信验证码，验证通过后设置登录密码完成注册。
 
2.5 推荐注册奖励（可选）
若注册时填写推荐人手机号（推荐人需为系统内已存在的用户），注册成功后系统自动向推荐人发放推荐积分奖励。推荐关系仅用于发放一次性奖励，不构成业务绑定关系，不影响后续该用户从哪个经销商处获得积分。

三、积分体系与操作流程
3.1 积分来源与流转说明
重要原则：系统中所有积分的唯一创建入口为管理端（厂商），一级经销商、二级经销商、终端客户均无法创建积分，只能使用或转移已持有的积分。
积分来源	获取方	触发条件	说明
平台分发	一级经销商	厂商在管理端手动分发	唯一的积分创建入口
上级赠送	二级经销商、终端客户	上级经销商在商家端操作	经销商将自己持有的积分转移给下级
首充赠送	所有会员	首次充值成功	系统自动从平台积分池发放
注册赠送	所有会员	注册成功	系统自动从平台积分池发放
每日签到	所有会员	每日签到	系统自动从平台积分池发放
推荐注册	推荐人	被推荐人注册成功	系统自动从平台积分池发放
积分红包	所有会员	会员之间互赠	用户将自己持有的积分转移给他人
抽奖获得	所有会员	抽中积分类奖品	系统自动从平台积分池发放
积分流转层级：厂商（创建）→ 一级经销商（持有/赠送）→ 二级经销商（持有/赠送）→ 终端客户（持有/消费）
3.2 积分分发流程（管理端→一级经销商）
厂商在管理端选择目标一级经销商，输入分发积分数量。系统向厂商操作人员手机发送短信验证码，厂商填入验证码后确认分发。分发成功后，一级经销商积分余额增加，同时生成积分流水记录，记录内容包含操作时间、操作类型（平台分发）、积分数量、接收方信息、操作人。
 
3.3 积分赠送流程（经销商→下游用户）
经销商在商家端扫描用户的会员码，或手动输入用户手机号，系统显示该用户信息（姓名、身份类型）供确认。经销商输入赠送积分数量，系统校验经销商自身积分余额是否充足（赠送本质是将自己持有的积分转移给对方，而非创建新积分）。校验通过后，系统向经销商手机发送短信验证码，经销商填入验证码后确认赠送。赠送成功后，经销商积分余额减少，接收方积分余额增加，双方均生成积分流水记录。
 
赠送规则：
•	一级经销商可向任意二级经销商或终端客户赠送积分
•	二级经销商可向任意终端客户赠送积分
•	赠送数量不可超过经销商当前积分余额
•	无需事先建立绑定关系：经销商可以给任何已注册的下游用户赠送积分，典型场景如顾客到店消费后获得积分奖励
•	经销商无法凭空创建积分，所有积分均来源于上级分发或赠送
3.4 积分红包流程（会员互赠）
此功能可由管理端控制开关，关闭后所有用户不可使用该功能。功能开启时，任意会员可在客户端向其他会员发送积分红包。发送方输入接收方手机号和红包积分数量，系统校验接收方手机号是否为系统内有效用户，校验发送方积分余额是否充足。校验通过后，系统向发送方手机发送短信验证码，发送方填入验证码后确认发送。发送成功后，积分即时到账，双方生成积分流水记录。
3.5 签到积分流程
用户在客户端点击每日签到按钮，系统判断该用户当日是否已签到。若未签到，则签到成功，系统按管理端配置的签到赠分规则增加用户积分余额并生成流水记录。若当日已签到，则提示"今日已签到"。签到周期以自然日为单位，每日0点重置签到状态。
3.6 推荐注册积分流程
被推荐人在注册时填写推荐人手机号，注册成功后系统自动向推荐人发放推荐积分奖励。推荐积分数量由管理端配置。推荐人需为系统内有效用户（经销商或会员均可）。推荐关系仅在注册时建立，不影响用户的层级归属关系。
3.7 首充与注册赠分流程
管理端可配置注册赠分数量和首充赠分数量。用户注册成功后，系统自动发放注册赠分。用户完成首次充值后，系统自动发放首充赠分。充值功能作为预留接口，具体充值方式待后续对接。

四、商品管理与兑换流程
4.1 商品类型定义
商品类型	说明	兑换后交付方式
实体商品	需要物流配送的实物商品	填写收货地址，物流配送
虚拟商品	数字化商品或服务	系统直接发放
商品券	可在线下核销的电子券	生成券码，商家端扫码核销
4.2 商品上架流程（管理端操作）
厂商在管理端新建商品，填写商品名称、商品分类、积分价格、商品图片、商品描述、库存数量，选择商品类型。若为商品券，还需设置券有效期（固定日期或自兑换之日起N天）。填写完成后提交，商品进入"已上架"状态，客户端可见。厂商可随时将商品设为"已下架"状态，下架后客户端不可见但历史订单不受影响。
4.3 商品分类管理（管理端操作）
厂商在管理端可创建、编辑、删除商品分类。分类仅支持一级，不设置多级分类。删除分类时，若该分类下存在商品，需先将商品移至其他分类或删除商品后方可删除该分类。
4.4 实体商品兑换流程
 
4.5 商品券兑换流程
用户在客户端选择商品券类型商品，确认兑换。系统校验积分余额充足后，扣减用户积分，生成唯一券码（16位数字+字母组合，系统自动生成），创建商品券记录，状态为"未使用"，同时记录券有效期。用户可在"我的商品券"中查看券码、有效期和使用状态。
券码生成规则：系统自动生成16位唯一码，格式为"字母+数字"混合，确保全局唯一。生成时自动排除易混淆字符（如0/O、1/I/L）。
4.6 虚拟商品兑换流程
用户在客户端选择虚拟商品，确认兑换。系统校验积分余额充足后，扣减用户积分，创建订单，状态直接为"已完成"。虚拟商品的具体发放方式根据商品性质确定，如积分类虚拟商品则直接增加用户积分。

五、订单管理与物流流程
5.1 订单状态定义
订单状态	说明	后续可变状态
待发货	实体商品兑换成功，等待发货	已发货
已发货	已填写物流单号，等待收货	已完成
已完成	用户确认收货或系统自动确认	终态
5.2 物流信息上传流程（管理端操作）
厂商在管理端查看"待发货"订单列表，选择订单进行发货操作。填写快递公司（从预设列表选择）和快递单号，点击确认发货。系统将订单状态更新为"已发货"，记录发货时间和物流信息。用户可在客户端订单详情中查看物流公司和快递单号。
5.3 物流查询流程（客户端操作）
用户在客户端"我的订单"中查看已发货订单详情，点击"查看物流"。系统调用第三方快递查询接口，传入快递公司编码和快递单号，获取物流轨迹信息并展示给用户。每次查询产生接口调用费用（约0.05元/次）。若查询失败，提示用户稍后重试或前往快递公司官网查询。
5.4 确认收货流程
用户可在订单详情中手动点击"确认收货"，订单状态变为"已完成"。若用户未手动确认，系统在发货后第15日自动确认收货，订单状态变为"已完成"。

六、商品券核销流程
6.1 核销操作流程（商家端操作）
经销商在商家端打开扫码核销功能，扫描用户出示的商品券券码（二维码形式展示）。系统查询该券码对应的商品券记录，显示券信息（商品名称、有效期、使用状态）供经销商确认。经销商确认无误后点击"核销"，系统将该商品券状态更新为"已使用"，记录核销时间、核销商家、核销操作人。核销成功后，用户端该商品券状态同步更新为"已使用"。
 
6.2 核销校验规则
核销时系统自动校验：券码是否存在，券是否在有效期内，券状态是否为"未使用"。任一条件不满足则核销失败，并向经销商提示具体失败原因。
6.3 核销权限说明
所有一级和二级经销商均可核销任意用户的商品券，核销权限不受层级归属限制。核销记录中会记录具体的核销商家信息，便于统计和追溯。

七、抽奖功能流程
7.1 抽奖配置流程（管理端操作）
厂商在管理端开启抽奖功能，从系统已上架商品中选择若干商品作为奖品，为每个奖品设置中奖概率（百分比形式，所有奖品概率之和加上"未中奖"概率等于100%）。设置单次抽奖消耗积分数量，设置每人每日抽奖次数上限。配置完成后保存并启用，所有客户端用户均可参与抽奖。厂商可随时在管理端关闭抽奖活动。
7.2 用户抽奖流程（客户端操作）
用户在客户端进入抽奖页面，系统显示当前抽奖活动信息（由管理端配置）。用户点击抽奖，系统校验用户积分余额是否满足单次抽奖消耗、当日抽奖次数是否已达上限。校验通过后扣减用户积分，系统根据配置的概率进行抽奖计算，返回抽奖结果。若中奖，根据奖品类型进行发放（实体商品创建待发货订单，商品券生成券码，积分直接增加余额）。若未中奖，提示用户未中奖。
 
7.3 抽奖开关说明
抽奖功能由管理端统一控制开关。功能关闭时，客户端不显示抽奖入口。功能开启时，所有客户端用户均可参与，不区分归属经销商。

八、会员码与扫码功能
8.1 会员码说明
每个用户注册成功后，系统自动生成专属会员码。会员码以二维码形式展示，包含用户唯一标识信息。会员码用途包括：商家端扫码识别用户身份、商家端扫码为用户增加积分、绑定未归属上级的用户。
8.2 扫码场景汇总
扫码场景	操作端	扫描对象	操作结果
识别用户	商家端	用户会员码	显示用户信息（姓名、身份类型）
赠送积分	商家端	用户会员码	进入积分赠送流程
核销商品券	商家端	商品券券码	进入核销流程

九、消息推送功能
9.1 推送类型
推送类型	说明	配置位置
系统通知	积分变动、订单状态变更等系统自动触发	管理端配置触发规则
推广消息	运营活动、促销信息等手动推送	管理端编辑并推送
9.2 推送范围
管理端可选择推送至全部用户、仅客户端用户、仅商家端用户，或按经销商层级筛选推送范围。
9.3 系统自动通知场景
积分余额变动时推送积分变动通知。实体商品订单发货时推送发货通知。商品券即将过期时（到期前3天）推送过期提醒。

十、数据视图与统计（管理端）
10.1 积分统计
可查看平台积分发放总量、各一级经销商积分持有量、积分流转明细（按时间范围、操作类型筛选）。
10.2 订单统计
可查看订单总数、各状态订单数量、订单金额（积分价值）统计，支持按时间范围、商品类型筛选。
10.3 核销统计
可查看商品券核销总量、各商家核销数量、核销明细（按时间范围、商家筛选）。
10.4 用户统计
可查看用户总数、各身份类型用户数量（一级经销商、二级经销商、终端客户）、新增用户趋势，支持按时间范围、身份类型筛选。

十一、系统配置（管理端）
11.1 积分规则配置
配置项	说明	默认值
注册赠分	新用户注册成功后赠送积分数量	0
首充赠分	用户首次充值成功后赠送积分数量	0
签到赠分	每日签到赠送积分数量	0
推荐赠分	推荐新用户注册成功后赠送积分数量	0
积分红包开关	是否允许会员之间互赠积分	开启
11.2 抽奖活动配置
配置项	说明
抽奖开关	控制抽奖功能是否对客户端用户开放
单次消耗积分	用户每次抽奖需消耗的积分数量
每日次数上限	每个用户每日最多可抽奖次数
奖品列表	从已上架商品中选择，设置每个奖品的中奖概率
未中奖概率	用户抽奖未中奖的概率（与所有奖品概率之和为100%）
11.3 快递公司配置
管理端预置常用快递公司列表（顺丰、圆通、中通、韵达、申通等），厂商可新增或删除快递公司选项。
11.4 客服配置
管理端可配置客服联系方式（电话、微信等），客户端展示客服入口供用户联系。

十三、收货地址管理
13.1 地址管理功能
用户可在客户端"个人中心"管理收货地址，支持新增、编辑、删除地址，设置默认地址。地址信息包含：收货人姓名、联系电话、省市区、详细地址。每个用户最多可保存10个收货地址。
13.2 地址选择流程
兑换实体商品时，若用户已有保存的地址，默认选择默认地址，用户可切换其他地址或新增地址。若用户无保存地址，需新增地址后方可完成兑换。

十四、安全与权限控制
14.1 登录安全
连续输错密码5次后，账户锁定30分钟。支持记住登录状态，有效期7天。
14.2 操作权限
各端用户只能访问其权限范围内的功能：管理端可进行全局配置和数据查看，商家端可进行积分赠送和商品券核销，客户端可进行商品兑换和积分使用。管理端操作日志完整记录，便于审计追溯。
14.3 积分安全
所有积分发放、赠送操作均需短信验证码确认，防止误操作和恶意操作。积分流水记录完整保存，可追溯每一笔积分变动的来源和去向。

附录C：名词解释
名词	解释
厂商/平台方	系统最高管理者，使用管理端进行系统配置、积分创建和数据管理
一级经销商	由厂商创建的经销商账户，可接收厂商分发的积分，可向二级经销商和终端客户赠送积分
二级经销商	由一级经销商创建的经销商账户，可接收一级经销商赠送的积分，可向终端客户赠送积分
终端客户	最终消费者，可接收任意经销商赠送的积分，只能使用客户端进行积分兑换

商品券	可在线下核销的电子券，兑换后生成唯一券码
积分流水	积分变动的详细记录，包含时间、类型、数量、对方信息等
积分流转	积分从上游向下游转移的过程，厂商→一级经销商→二级经销商→终端客户
